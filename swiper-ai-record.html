Swiper 课堂任务 · AI 提示词与验证记录

周丽 · 2026-11-09 · 使用模型：GLM-5.3-Flash · 对应教师版《Swiper 轮播组件库 · 大国重器光影展》第 6 节"课堂任务 + 思政升华"

任务一 · 提示词工程师：让 AI 听懂需求 ⭐⭐

第 1 轮提示词（原始版，凭直觉写的）

帮我用 Swiper 写一个轮播配置：自动播放，每 3.2 秒翻一页，可以循环，加圆点分页器，效果用 cube。

第 1 轮 AI 回答（v1）

new Swiper('#wySw4', {
  loop: true,
  autoplay: { delay: 3200 },
  effect: 'cube',
});

第 1 轮问题分析（对照 4 条需求逐条检查）

  • ① 无缝循环：满足，loop: true 正确
  • ② 3.2 秒自动翻页且手动操作后不停止：半对——漏了 disableOnInteraction: false，Swiper 默认用户一拖动自动播放就永久停止
  • ③ 圆点分页器可点击跳转：未满足，分页器整段缺失
  • ④ 初始效果为 cube：满足

第 2 轮提示词（把每条需求"说清楚"后的精确版）

用 Swiper 11 给 #wySw4 写初始化配置，共 4 条硬性要求，一条都不能漏：
① loop 无缝循环；
② 自动播放 delay 为 3200 毫秒，并且加上 disableOnInteraction: false——
   用户手动拖动后自动播放不能停；
③ 分页器挂载到 #wyPag3（注意 el 必须写），且 clickable: true 圆点可点击跳转；
④ 初始 effect 用 'cube'，切换动画时长 speed: 800。
请逐条对照检查后再输出。

第 2 轮 AI 回答（v2，最终采用）

new Swiper('#wySw4', {
  loop: true,
  effect: 'cube',
  speed: 800,
  autoplay: { delay: 3200, disableOnInteraction: false },
  pagination: { el: '#wyPag3', clickable: true }
});

亲自验证：运行时注入配置 + 浏览器逐条实测（附截图与一句话结论）

cube 生效：容器出现 swiper-cube 类，3D 立方体旋转切换正常（验证后已还原现场）。
圆点可点击跳转：点第 3 个圆点即跳到第 3 张且圆点高亮；自动播放 3.2 秒、循环、拖动后不停止（autoplayRunning 为 true）四条全部满足。
答辩抽问 · 第一版漏了哪个需求？②的"手动操作后不停止"（漏 disableOnInteraction: false）和 ③分页器整段。
第二轮怎么"说清楚"的？把"自动播放"拆成 delay + disableOnInteraction 两个参数点名；给分页器写明 el 挂载点和 clickable；并要求 AI"逐条对照检查后再输出"。
AI 第一次的代码错在哪？不是语法错误，而是默认值陷阱——disableOnInteraction 默认为 true，不写就与需求相反；这提醒我 AI 的代码必须对着需求逐条验证。

任务二 · creative 仿写：课堂没讲，AI 教你 ⭐⭐⭐

实现方式

演示四新增第 7 个按钮 data-fx="creative"；动态换 effect 必须销毁重建，重建配置统一放进 zhouliFxConfig，选中 creative 时追加 creativeEffect：

creativeEffect: {
  limitProgress: 2,
  shadowPerProgress: true,
  prev: { translate: ["-42%", "-8%", -280], rotate: [0, 0, -10],
          scale: 0.72, opacity: 0.55, shadow: true },
  next: { translate: ["96%", "6%", 0], rotate: [0, 0, 8],
          scale: 1.15, opacity: 0.9, shadow: true }
}

亲自验证（附截图与一句话结论）

prev 缩小、左移、逆时针倾 10 度、半透明退墙后；next 放大、从右侧 96% 处带 8 度角进场——层叠错落如电影选片墙，切回 cube/slide 均正常。

用自己的话回答：prev / next 的 transform 各控制什么？

  • prev 控制"已经翻过去的上一张"退场后停在哪里：它决定上一张以多大的位移、缩放、旋转角、透明度"挂"在当前张背后——相当于照片墙上已经看过的那张海报的样子。
  • next 控制"还没翻的下一张"以什么姿态等着进场：它决定下一张翻页前"埋伏"的位置和大小，翻页时它就从 next 描述的状态动画过渡到正常状态。
  • 合起来：prev 是"过去时"的站位，next 是"将来时"的站位，Swiper 只负责在两个状态之间做补间动画。
答辩抽问 · transform 里的百分号相对谁？translate 的 x 相对 slide 自身宽度、y 相对 slide 自身高度（不是容器也不是视口），所以 "96%" 就是往右挪一张 slide 的宽度再多一点。
改一个数值让卡片转 20 度？把 rotate 的第三个值（z 轴角度）从 -10 改成 20：rotate: [0, 0, 20]，上一张就会顺时针翘起 20 度。

② 课堂没讲过的能力：keyboard 键盘控制

与 AI 的关键对话：问 AI"Swiper 想用键盘方向键翻页怎么配"，AI 给出：

keyboard: { enabled: true, onlyInViewport: true }

追问：这两个参数各是什么作用？AI 解释后我自己的话总结：

  • enabled: true——开启键盘控制，按 ←/→/↑/↓ 等方向键即可翻页；
  • onlyInViewport: true——只有轮播滚动到可视区域内时方向键才归它管，防止页面其它地方按方向键（比如滚动网页）被轮播"劫持"。

亲自验证（附截图与一句话结论）

滚动到可视区后按方向键 activeIndex 3→4 键盘翻页生效；连按两次仅 +1 是因为第二次按键落在 800ms 切换动画期间被动画队列吸收——如实记录；onlyInViewport 下页面其它位置按键不受影响。
答辩四连问 1 · 这段代码什么意思？见上，keyboard 模块两参数分工明确。
2 · AI 第一次给的哪里不对、你改了什么？AI 最初只给 keyboard: true（简写形式），功能可用但缺 onlyInViewport 保护，长页面里会干扰正常滚动，因此补全为对象写法。
3 · 新参数的作用？onlyInViewport 限定轮播在可视区内才接管方向键。
4 · 现场把 delay 改成指定值？把 autoplay.delay 从 3200 改成如 1500，预期自动翻页间隔缩短到 1.5 秒，肉眼可感知翻页明显变快；disableOnInteraction: false 不受影响。
